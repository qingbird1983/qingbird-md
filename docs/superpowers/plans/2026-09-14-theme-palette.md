## 1. 选色原则：为什么是这六套

这是「长时间读中文长文 + 中英对照翻译」的工具，配色不是审美题，是**疲劳题**。定下 5 条硬约束，六套全部按它校准：

1. **纸面恒暖或恒中性，杜绝纯白 `#fff` 大底**
   纯白在 400+ 尼特屏上连续阅读半小时会明显发涩（对比过载）。六套的纸面亮度都压在 `#f5` ~ `#fa` 之间，靠**温度**区分而不是靠亮度。
2. **全界面只有一个彩色**
   彩头只给「翻译语义」（译文标记、双语对照、进度）。多了就与朱砂抢注意力——而朱砂承担的是「警告/未保存」这种**必须被看见**的信号。
3. **彩头与朱砂的色相差 ≥ 60°**
   朱砂色相恒在 **7°** 左右。彩头必须离它至少 60°，否则「译文蓝」和「警告红」在小尺寸图标上会互相冒充。
4. **四档对比度门槛**（WCAG AA 的加强版，因为本应用里有 9.5px 的分区标题小字）
   | 令牌对 | 门槛 | 理由 |
   | --- | --- | --- |
   | 主墨 `--fg` / 纸面 | **≥ 10.0** | 正文长读，越松越好；现状 14.98 属舒适区 |
   | 次级 `--fg2` / 纸面 | ≥ 7.0 | 菜单项、树行 |
   | 弱墨 `--fg3` / 纸面 | **≥ 4.5** | 9.5px 分区标题 / 空态（**现状只有 3.11，不达标**） |
   | 彩头 / 纸面、朱砂 / 纸面、彩底上的字 | ≥ 4.5 | 文字与图标均按正文标准 |
5. **暗档不是浅档取反**
   暗底用低饱和墨色（`#17`~`#24` 区间，不用纯黑），彩头在暗档**提亮**（不是加深）以保住对比——纯黑 + 深彩会是本类应用最常见的廉价感来源。

### 一次被数据纠正的设计决定

初版第 4 套原本是「檀纸·**赭石**」（暖棕纸 + 赭石橙棕 `#8c5320`）。实测色相 **28°** vs 朱砂 **7°**，只差 **21°** —— 两者都是暖红橙系，选中态与警告态会在余光里糊成一片。

**改为「檀纸·藕荷」**：纸底保持暖棕檀色不变，彩头换成藕荷紫 `#6f5486`（色相 **272°**，与朱砂差 **94.5°**）。暖棕纸 + 藕荷紫是传统书画里很常见的搭配（檀皮纸配紫毫），比赭石更雅，也把六套里唯一的**非冷色彩头**补上了。

## 4. 落地设计

### 4.1 数据模型与持久化

配方色归入 **Rust `Settings`**（与 `theme` 同层，不是会话快照）：

```rust
// src-tauri/src/storage.rs
/// 配色 id（xuan/su/qing/tan/ci/ye）；"" = 默认 xuan。与 theme（明暗）正交。
#[serde(default)]
pub palette: String,
```

`#[serde(default)]` 让老配置文件读出来是空串 → 回落到 `xuan`，**升级零感知**。

前端 `useSettingsStore` 平级新增 `palette` + `setPalette()`，与 `setTheme` 完全同构（`save()` 一次点亮 + 落盘，靠后端 `settings-updated` 广播跨窗口同步）。**注意沿用 `setTheme` 那个坑的写法**：不能先 `applyTheme` 再判断 `cur.theme !== t`，否则守卫恒假、盘上无落痕。`palette` 的守卫同样写成读 `cur.palette` 再比。

### 4.2 DOM 契约

```
body[data-theme="light|dark"]      ← 已有（isDarkTheme 解析后写入，auto 跟随系统）
body[data-palette="<id>"]          ← 新增；xuan 时**不挂**属性（省一层覆盖，且等于现状）
```

`syncDomTheme` 里一次性写两个属性（它已经是唯一的主题 → DOM 出口）。CSS 侧只需两种选择器：

```css
body[data-palette="qi"] { … }                          /* 浅档 */
body[data-theme="dark"][data-palette="qi"] { … }        /* 深档（两层属性，特异性更高，天然覆盖） */
```

### 4.3 单一真源 + 生成（防止 12 套令牌漂移）

6 套 × 2 档 × 19 枚 = **228 个色值**。手写两处（种子 + CSS）必然漂移，所以：

```
src/lib/paletteSeeds.ts          ← 唯一真源：6 套 × 2 档的种子对象 + 元数据（label/note）
scripts/gen-palettes.mjs         ← 由种子生成 src/styles/palettes.css（含注释头「勿手改」）
src/lib/paletteSeeds.test.ts     ← 双重守卫：① 对比度门槛 ② 生成物与种子一致
```

- `npm run gen:palettes` → 重新生成 CSS；忘了跑会被测试挡住。
- 对比度测试直接复用 §1 的 4 档门槛，12 档全过。
- 派生令牌（`--border-strong = mix(border, fg3, 0.25)`、`--accent-weak/ring`、`--zhu-wash`）全部由脚本算，手不碰。

> 若嫌生成脚本重：退路是只留 `paletteSeeds.ts` + 运行时写内联 CSS 变量。**不推荐**——内联样式会盖掉 `theme.css` 里 `body[data-theme="dark"]` 的 `--shadow-*` / `--item-hover-bg` 等非种子令牌，两套来源打架比生成脚本麻烦得多。

### 4.4 已知约束：代码高亮 token 色不随配色变（**必须先说清**）

代码块的 token 颜色是**后端 syntect 烘进内联样式**的（`html.rs` 的 `--cl` / `--cd` 双主题对，选择逻辑在 `markdown.css` 按 `body[data-theme]` 选边）。

**这意味着换配色时，代码块背景会跟着变，但 token 前景色不会。** 三个选项：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| **A. 保持现状（推荐 v1）** | 代码高亮固定用 base16-ocean（亮/暗各一），只有背景随主题 | 暖纸底 + 冷调高亮，个别配色（`qing` / `tan`）会略跳 |
| B. 按配色换高亮主题 | 每套配色挑一个 syntect 主题，重渲染代码块 | 动渲染管线 + **缓存键要加配色维度**（否则缓存串色）；成本最高 |
| C. 只在 CSS 层做色相微调 | 用 `filter: hue-rotate()` 之类的 hack | 不可控、会误伤图片，**不建议** |

建议 v1 走 A，把 B 列入后续（它本质上要求 `Cache::key` 增加 palette 维度，属独立需求）。

### 4.5 受影响的其它出口

| 出口 | 要做的事 |

### 9.1 R1「换主题色后标题栏没跟着换色」——根因与修法

**根因（已用浏览器引擎实证，非推测）**：CSS 自定义属性在**声明它的那个元素**上就把 `var()` 替换成具体值（computed-value time），替换结果再按继承往下传。

`theme.css` 里 `--panel-bg: var(--bg2)` 原先只写在 `:root`(=html) 上 → 它在 html 上就锁定成 html 的 `--bg2`（= 默认档 xuan 的暖纸色）继承给整棵子树；而 `palettes.css` 的配色覆盖写在 **body** 上 → 浅档的标题栏/侧栏/状态条/按钮底纹丝不动。
**暗档此前侥幸正常**：`body[data-theme="dark"]` 里重复声明过一遍同样的别名，替换点恰好落回 body —— 这也正是这个坑长期没被发现的原因。

同族受害者不止 `--panel-bg`：`--btn-bg` / `--btn-border` / `--btn-hover-bg` / `--tree-selected-bg` / `--palette-selected-bg` / `--caret-fg` / `--muted-fg` / `--note-fg` / `--test-fg` / `--status-fg` / `--danger` / `--tr-track-bg` 共 13 枚都是同一写法。其中 `--tree-selected-bg`、`--palette-selected-bg` **连暗档都没重复声明**，所以它们在深色下也一直是错的（树选中行本会变成近白底）。

**修法**：13 枚派生令牌从 `:root` 与 `body[data-theme="dark"]` 全部搬到新的 `body { … }` 段；`:root`/暗档只留字面量。顺带定下规矩：**body 段只允许引用基础令牌，不许「别名引用别名」**。
先例其实早就在仓库里：`markdown.css` 的 `--md-*` 本来就声明在 `.markdown-body`（body 后代）上，所以阅读区一直是跟得上配色的——只有 `theme.css` 那批没搬。

**实证方法**（新增 `scripts/css-probe.py`）：把真实三份 CSS 拼成静态页，用无头 Edge 读计算值，断言**关系**（`.titlebar` 底色 == body 的 `--bg2`）而非硬编码色值，6 套配色 × 2 档 × 6 个探针，全 MATCH 且退出码 0。修复前该探针在浅档必红。
另一条守卫是 `src/lib/themeAlias.test.ts`（结构化断言：别名只能声明在 `body`，`:root`/暗档不得出现 `var()`）——vitest 里没有真实浏览器，行为只能交给 css-probe，结构交给单测。

### 10.3 LLM 翻译源：从「预设下拉」改成「可持久化的多档案」（R8）

**问题（用户原话）**：LLM 大模型源与下面的「厂商预设」下拉是**重复项**——选预设会把自定义清掉，自定义只能存一份，拉取的模型列表关窗即丢，「想自定义多家无法做到」。

**根因**：数据模型里只有**一处**凭据槽（`providers["llm"]`），翻译管线只读它。预设下拉与自定义输入在同一个槽上互相覆盖，**没有任何持久层能存第二份**——所以这不是 UI 排列问题，是缺一层数据结构。

**新架构（分层，管线零改动）**：

- Rust `Settings` 新增 `llm_profiles: Vec<LlmProfile>` 与 `llm_active: String`（均 `#[serde(default)]`，老配置无痛加载）。
  `LlmProfile { id, name, base_url, api_key, model, lookup_model, models: Vec<String> }`
- **档案 = 可持久化的「已存配置库」**；翻译管线仍然只认单一凭据槽 → 「选用某档案」= 把它的值**镜像**进槽。管线不知道档案的存在，故无需改协议。
- **厂商预设降级为「新建档案时的模板」**，不再是并列的第二个下拉 → 重复项消失。UI 上「＋ 新建配置…」里列预设。
- 档案列表 `.prof-list`：每行 = 名称输入 + base_url 摘要 + 「使用中」标 + 删除钮；删除即真删该档案（用户明确要求「不需要的要有删除当前自定义的功能」）。
- **模型列表落进 `profile.models`** → 关窗重开仍在，且可在其中挑选用哪个 → 解决「拉取模型不能长久保存」。
- 本区**单独给一个「保存此配置」按钮**（用户明确要求）。

**迁移（一次性闩锁，含一个被单测抓出的真 bug）**：老配置若 `providers.llm` 非空而 `llm_profiles` 为空，自动收养成一份「原有配置」档案。必须用 `useRef(migrated)` 做**一次性**闩锁——否则「删掉最后一份档案」会让 `llm_profiles` 回到空，迁移逻辑立刻把它复活。这条是测试先发现、后修的（产品 bug，不是测试 bug）。

### 11.3 数据目录的显示形态（R3）

**先澄清一件事**：`storage::user_data_dir()` 是每次启动现算的（`dirs::data_dir()`），**换电脑本来就不会错**。用户看到 `C:\Users\<用户名>\...` 以为路径被写死了——问题出在**显示**，那就改显示。

**改法**：新增 `storage::user_data_dir_label()` + 命令 `get_data_dir_label`，把用户数据根折成 `%APPDATA%\qingbird-md`。
- **两条路必须分开**：显示走 `get_data_dir_label`；要打开目录仍走 `get_user_data_dir` 的**绝对路径**（把 `%APPDATA%` 原样交给 explorer 是解析不出来的）。命令分开而不是加参数，就是为了让这件事在签名上就看得见。
- **前缀替换要卡分隔符边界**（`strip_dir_prefix`）：否则 `C:\Users\ab` 会匹配上 `C:\Users\abcdef\...`，把别人的目录误认成家目录。已用单测钉住。

## 12. 第五轮修订（2026-09-14，用户 3 条，纯视觉打磨）

**本轮全是 CSS，零逻辑改动**——三条都在 `global.css`，`tsc` 与 160 条测试（含左栏结构断言）原样通过，说明这轮动的是「观感」而非「契约」。

### 12.1 印章改居中（R1）

上一轮把印的左缘对齐到了导航项的**图标列**（左边距 10px）。这在几何上「对齐」了，读起来却不对：**看起来像列表里的第一项**。

**改法**：`margin: 2px 0 12px 10px` → `margin: 2px auto 16px`，水平居中；下边距 12→16px 顺带把印章与分类之间拉开一点层次。
- 语义上印章是**栏目头**，不是导航项——居中与下方左对齐的文字分类形成对比，层次这才出来。
- 注释同步重写（原来那段「10px 对齐图标列」的解释已失效，留着会误导后人）。

### 12.2 分类行距加大（R2）

`gap: 2px` → `4px`，`.set-nav-item` 的 `padding: 8px 10px` → `9px 10px`，`.set-nav` 自身 padding 顶 12→14px。

**为什么两个都动**：只调 `gap` 会让项与项之间空、但每项自身仍显扁；只调 padding 则相邻项贴得紧。两者一起加，`gap` 管「分隔感」、`padding` 管「项本身的分量」。

### 12.3 搜索胶囊缩短（R3）

**问题**：`.set-search` 原本 `flex: 1`——**铺满整条工具条**（980px 面板下右栏 756px，胶囊就吃掉约 700px），一条空的长胶囊压在顶上看感很怪。

**改法**：`flex: 1` → `flex: none; width: 320px; max-width: 100%; margin-left: auto`。
- **定宽而不是百分比**：百分比会随窗口一直变，长度不可控；320px 是「够输入两三个关键词、又不喧宾夺主」的折中。
- `margin-left: auto` 把胶囊顶到右侧贴着关闭叉；`max-width: 100%` 保证窄窗时自然收缩不溢出。
